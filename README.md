# 数据湖仓一体管理平台

面向数据湖仓一体架构下的多源异构接入、原始文件编目、湖内分区治理、流批一体转换、版本回溯与数据编目检索的管理平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 质量阈值版本化

阈值口径统一收在 `backend/app/services/quality_registry.py`，路由层只做参数透传：

- **版本**：每次阈值（或告警级别、业务优先级）调整生成一个 `QV-xxxx` 版本；重复提交同一修改
  （阈值、告警级别、优先级都与当前生效值一致）复用当前版本，不新增版本号。
- **重判**：调整后对已启用指标按新口径生成新批次；历史批次保留当时阈值、判定与告警级别
  （`GET /api/quality/results?days=7`，字段 `历史口径` 标记）。未启用指标只登记版本。
- **告警**：已发生告警的 `触发阈值`/`阈值版本`/`告警级别` 是快照，不随调整改写；
  `恢复阈值`/`恢复阈值版本` 读取当前生效版本，恢复策略按新口径执行。
- **冲突**：同一监控对象多个指标同时异常时按业务优先级（P0>P1>P2>P3）裁决，优先级相同再取
  告警级别更高者（严重>一般>提示）。见 `GET /api/quality/conflicts`。
- **同步**：阈值调整同步到聚合视图（`质量阈值`/`阈值版本`）与治理规则（`触发阈值`/`阈值版本`），
  两个入口读取同一份告警级别；`GET /api/quality/version-sync` 可核对一致性。
- **校验**：阈值只接受 0~1 的单值或 `a~b` 区间，超范围返回 400 且不保存。
- 阈值调整入口：`POST|PUT /api/quality/{id}/threshold`，请求体
  `{"values": {"阈值范围": "0.995", "告警级别": "严重", "业务优先级": "P1", "备注": "..."}}`。

示例数据里 `QUAL-0001`（监控对象「销售额」）已按业务要求从 `0.98` 调整为 `0.995`，
过去七天检测结果仍保留当时口径。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
